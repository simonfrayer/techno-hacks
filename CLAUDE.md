# techno-hacks: medicine intake + storage monitor

An Atech board (ESP32-S3, 14port) records spoken medicine details. A Python
bridge on the laptop, connected over USB, transcribes them and extracts name,
expiry and tablet count. The user picks a storage place on the board, and the
record is stored in SQLite. The board also watches the storage temperature and
humidity.

Architecture (since 2026-11-21): **atech SDK firmware + USB bridge.** The
atech.dev web build (WiFi gateway, `P2PCommand`) is no longer used. Its original
`main.cpp` is kept for reference in `firmware/reference/atech_dev_main.cpp`.

## Layout

| Path | What |
|---|---|
| `firmware/project.yaml` | atech project: board, module ports, glue code. `firmware/CLAUDE.md` is the SDK guide (`atech guide`) |
| `firmware/app/medtracker.h` | **all firmware app logic** (namespace `med`), included from project.yaml `code: globals:` |
| `firmware/build/` | generated by `atech build`, never edit (gitignored) |
| `src/techno_hacks/` | Python: `bridge.py` (USB <-> backend), `backend.py`, `audio.py` (mu-law, WAV), `extract.py` (transcript -> details), `transcribe.py` (pluggable STT), `store.py` (SQLite), `cli.py` |
| `tests/` | pytest. The bridge is tested against a fake board |
| `medtracker.toml` | places + climate limits that the bridge pushes to the board |
| `data/` | SQLite DB + WAV recordings (gitignored) |

## Commands (from the repo root)

```bash
uv run atech validate firmware && uv run atech upload firmware   # build + flash
uv run techno-hacks bridge [--whisper-model small.en] [--transcriber whisper|manual|fixed] [-v]
uv run techno-hacks stt-check --say "Ibuprofen 400, expires March 2027, 20 tablets"
uv run techno-hacks records [--climate]
uv run pytest
uv run atech monitor / atech send <action> <value>               # debugging (not while the bridge runs)
```

- Build with the **CLI from the repo root** (`atech build firmware`). project.yaml
  includes `../../app/medtracker.h` relative to `firmware/build/src/main.cpp`.
  The Python `Project.build()` default output dir would break that path.
- Only one program can hold the serial port: the bridge, `atech monitor`,
  `pyserial-miniterm` or an atech.dev Web Serial tab. Check with
  `lsof /dev/cu.usbmodem1101` (run by the user; the sandbox cannot see other
  processes or open the port).
- **Flashing on this board (2026-11-21):** `atech upload` failed with "Failed to
  connect to ESP32-S3: No serial data received". The USB-JTAG auto-reset did not
  get the chip into download mode. What worked was flashing by hand:
  1. Put the board in download mode: hold BOOT, tap RESET, then release BOOT.
  2. Run esptool directly with `--before no-reset`, from
     `firmware/build/.pio/build/esp32-s3-devkitc-1/`, after `atech build firmware`:
     ```bash
     ~/.platformio/packages/tool-esptool/esptool --chip esp32s3 --port /dev/cu.usbmodem1101 \
       --before no-reset --after hard-reset write-flash -z 0x0 bootloader.bin 0x8000 partitions.bin \
       0xe000 ~/.platformio/packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin 0x10000 firmware.bin
     ```
  3. Press RESET afterwards.

  Once the SDK firmware was on the board, plain `atech upload firmware` worked
  (2026-11-21). The manual way is only needed when that fails.
- Every build prints compiler warnings from the SDK-generated main.cpp and the
  SDK's drivers: unused `atechTruthy`/`atechNums`, deprecated pcnt/i2s drivers,
  `-Wreorder` in i2c_software, `%d` format in microphone.cpp. They are harmless.
  Only warnings in `firmware/app/medtracker.h` are ours.
- The toolchain is PlatformIO espressif32 with **Arduino core 3.3** (not 2.0 as the
  SDK guide says). The first build downloads about 2.4 GB into `~/.platformio`.
  A clean build takes about 2 min.

## User flow

1. **Hold the button** and say the product name, expiry date and tablet count.
   Recording runs **as long as the button is held, up to 15 s**. Releasing it
   (60 ms debounce) stops the recording. Under 0.1 s shows "Too short".
2. The audio streams over USB to the bridge (`UPLOADING`, then `WAIT_VOICE`).
3. When the bridge answers `voice`, the screen shows the details above the list of
   storage places (`MENU`).
4. **Turn the knob** to choose a place. **Press the knob** to confirm. The button
   does not confirm.
5. The `record` event goes to the bridge (`WAIT_SAVE`).
   - If it is saved, the screen shows **SAVED** and the top light row turns green.
   - On an error, or no reply within **15 s**, the screen shows **TRY AGAIN** and
     the top row turns red.
   - The top-row colour stays until the next recording. The result screen goes
     back to READY after 4 s.
6. Temperature and humidity are reported **every 15 s** (`report_seconds` in
   medtracker.toml; changed from hourly on 2026-11-21), at startup, and on every
   status change.

Other timeouts:
- Waiting for the transcript: 60 s ("No transcript"). Pressing the button there
  cancels.
- Upload with no computer reading the port: 20 s ("No computer").
- `voice_error` shows TRY AGAIN without changing the top-row colour.

## Light and climate

- **Row 0** shows the record status: blue while recording, light blue while
  busy, then green or red for the last save.
- **Rows 1–2** show the storage climate: green is ok, orange is near a limit, red
  is over a limit, grey is no reading.
- Default limits are **2–26 °C** and **humidity at most 50 %**. "Near a limit"
  means within **1 °C** of either temperature limit or within **5 points** of the
  humidity limit. The sensor is read every 15 s, and the screen's bottom line (`23.4C 45%`)
  redraws whenever the shown value changes.

## Protocol (atech events/actions over USB)

Board → bridge events are `event_type: state` with these keys:
- `audio_start` `{id, rate:8000, bits:8, encoding:"mulaw", bytes, chunk:96}`
- `audio` `{id, seq, d}`, where `d` is base64 of 96 bytes. A chunk is sent only
  when the USB TX buffer has room for the whole line.
- `audio_end` `{id, chunks, bytes}`
- `record` `{id, name, expiry, quantity, place}`
- `climate` `{temp_c, humidity, status: ok|warning|alarm, reason, t_min, t_max, h_max}`
  or `{ok:false, reason}`
- `ui_state` (state name), `app_info` (sent at boot; the bridge then re-sends the
  config), `places` `{count}`, `recording_full`.
- The SDK's own module events also arrive: `button_module`,
  `rotary_encoder_knob`, `microphone_level` (every 250 ms),
  `aht20_sensor_temperature` / `_humidity` (every 2 s).

Bridge → board actions (each acked; failures come back as `ok:false` with a reason):
- `voice`: `{"id","name","expiry","quantity"}` or `name|expiry|qty`. It is only
  accepted in wait_voice, idle or result; elsewhere it fails with "busy".
- `voice_error` (message), `saved` `{id}`, `error` `{id,msg}`. A wrong id fails
  with "stale id".
- `audio_resend` (seq): the board sends that chunk again.
- Config: `places` (comma list, at most 10 × 23 characters), `limits`
  `{t_min,t_max,h_max}`, `climate_now`, `report_seconds` (min 5; `report_minutes` still accepted), `knob_reverse`,
  `cancel`.

Board screen text is ASCII only. The bridge's `screen_text()` transliterates
(ü→ue, ß→ss). Do not send `\uXXXX` escapes: the firmware JSON reader drops
backslashes.

## Backend

- **Transcription:** local Whisper via `faster-whisper` (`transcribe.py`,
  `WhisperTranscriber`). It is the default.
  - The default model is `base.en`. `--whisper-model small.en` is more accurate
    on drug names.
  - It runs int8 on the CPU and handles 11 s of audio in about 0.5 s on Apple
    Silicon.
  - The model downloads once to `~/.cache/huggingface` and works offline after
    that.
  - An `initial_prompt` primes Whisper with the expected sentence shape. VAD
    trims the silence.
  - The WAV is read by our own `load_wav_16k()` and passed as an array, because
    faster-whisper 1.2.1's PyAV decoding breaks with PyAV 19 (`metadata_errors`
    kwarg).
  - Other modes: `manual` (you type what was said) and `fixed`. Every recording
    is kept as `data/recordings/<id>.wav`.
  - `techno-hacks stt-check --say "..."` or `stt-check <wav>` tests STT +
    extraction without the board, through the board's 8 kHz mu-law path.
- **Extraction:** `extract.py` is rule-based (English). It understands month
  names, numeric dates and number words. Expiry is normalised to `YYYY-MM` or
  `YYYY-MM-DD`.
- **Audio:** 8 kHz G.711 mu-law (2:1 pair-averaged from the mic's 16 kHz). The
  bridge decodes and normalises it, and writes a 16-bit WAV.
